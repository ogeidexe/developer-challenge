# Data Dictionary

> Semantics, formats and ownership for every persisted field. Physical types live in ERD-PHYSICAL.md;
> this dictionary answers *what the value means, its format, who writes it, and who reads it*.

## Format conventions

| Convention | Meaning |
|---|---|
| `timestamptz` | UTC instant; serialized to clients as ISO 8601 with offset (NFR-020) |
| `*_cents` | Integer cents (BRL). Serialized as decimal string with exactly 2 fraction digits: `1299990` → `"12999.90"` |
| `char(7) yyyy-mm` | Competence/competence month in `America/Sao_Paulo` business time (BR-007) |
| UUID | RFC 4122 v4, generated by the database |
| Enums (`varchar` + CHECK) | Closed sets fixed by README §1.1, §2.2, §4.1 |

## users

| Field | Semantics / example | Written by | Read by |
|---|---|---|---|
| email | Login id, case-insensitive uniqueness (`SOL.MARIA@KINGSPAN.TEST`) | register/admin create | auth |
| password_hash | bcrypt(10+) / argon2id hash; **never serialized** | register/admin create/pw change | auth verify only |
| role | `SOLICITANTE` \| `APROVADOR` \| `ADMIN` (§1.1) | admin PATCH | access checks (`RequestAccess`), policies, audit |
| approver_level | `NIVEL_1` \| `NIVEL_2`; NULL unless role=`APROVADOR` | admin PATCH | chain eligibility, inbox |
| cost_center_id | Owning center; NULL = global admin | admin PATCH (or register) | visibility, eligibility |
| active | Deactivation flag (soft delete) | admin PATCH | login, `CurrentUser` (inactive users get 401) |
| lock_version | Optimistic lock for admin PATCH concurrency | system | `UserAdminService.update` (stale → 409) |

## budgets

| Field | Semantics / example | Written by | Read by |
|---|---|---|---|
| year_month | Month of competence `2026-11` | admin PUT (create) | consumption, dashboard |
| amount_cents | Monthly allocation; `1000000` = R$ 10.000,00 | admin PUT | dashboard, consumption guard |
| consumed_cents | Sum of totals of APPROVED requests in this competence month; incremented atomically at final approval | system (conditional UPDATE only) | dashboard, consumption guard, BUDGET_BELOW_CONSUMED check |
| invariant | `0 <= consumed_cents <= amount_cents` at all times (DB CHECK + conditional UPDATE) | — | — |

**Month without a row = zero balance** (BR-008): consumption lookup that finds nothing behaves as amount=0, consumed=0 → `BUDGET_EXCEEDED`.

## purchase_requests (aggregate root + working copy)

| Field | Semantics / example | Written by | Read by |
|---|---|---|---|
| request_number | Human id `REQ-000042`; DB sequence | system at create | display |
| owner_id | Creator; only owner edits/cancels (BR-017) | system at create | policies |
| status | Lifecycle state machine value (§4.1) | system via transitions | everything |
| current_version | Number of frozen versions; 0 = never submitted | system at submit | detail, versions, events |
| lock_version | Optimistic concurrency token; +1 on every mutation | system | 409 checks (NFR-021) |
| title / description / category / needed_by | Working copy (BR-012 on needed_by: future business date) | owner create/edit | detail, list, submit freeze |
| total_cents | Σ(quantity × unit_price) of **working copy**; equals current version total after submit; client value never accepted | system (MoneyCalculator) | list filters (min/maxAmount), sort |
| submitted_at | Last submit instant (UTC) | system | dashboard avg time [D], list |
| decided_at | Terminal instant (APPROVED/REJECTED/CANCELLED) | system | dashboard [D] |

| Field | Semantics | Written by |
|---|---|---|
| position | 0-based display/order key; UNIQUE per request | owner edit (wholesale replace) |
| description | Free text 1–255 | owner edit |
| quantity | Integer > 0 | owner edit |

## request_versions (immutable snapshots)

| Field | Semantics | Written by |
|---|---|---|
| version_number | 1, 2, 3… per request | system at submit (monotonic) |
| title/description/category/needed_by/total_cents | Frozen working-copy values at submit | system at submit |
| cost_center_id | **Frozen billing center of this version** — consumption charges this center, never the working copy's (A-28) | system at submit |
| competence_month | `to_char(now() AT TIME ZONE 'America/Sao_Paulo', 'YYYY-MM')` at submit | system at submit |
| submitted_by / submitted_at | Actor + UTC instant of freeze | system at submit |

Reads: `GET /requests/:id/versions(/:n)`, detail's current version, audit display.

## version_items

Frozen counterpart of `request_items` (same field semantics; `line_total_cents` CHECK enforced).

## approval_steps

| Field | Semantics | Written by |
|---|---|---|
| sequence | 1-based chain position; approved strictly in order | system at submit |
| level | `NIVEL_1` \| `NIVEL_2` \| `ADMIN` — from `ApprovalChainBuilder` | system at submit |
| status | `PENDING` → `APPROVED` (approve) · `PENDING` → `REJECTED` (reject) · `PENDING` → `RETURNED` (request-changes) · `PENDING` → `CANCELLED` (cancel while pending; current step only) · `PENDING` → `SKIPPED` (later steps, set in the same tx as a reject/return/cancel). A closed version never keeps a `PENDING` step. Decisions always update with `WHERE status='PENDING'` — 0 rows means someone decided first (409) | system at decision |
| approver_id | Deciding user; set on any decision | system at decision |
| decided_at | UTC decision instant | system at decision |
| comment | Optional on approve (any length ≥ 1); mandatory ≥ 10 chars on reject/return per CommentPolicy | approver (copied by system) |

DB guarantee: a step is decided at most once — decisions always run
`UPDATE approval_steps … WHERE id = :id AND status = 'PENDING'`; 0 rows means someone decided first
(the aggregate lock already serialized same-request races; see TRANSACTION-STRATEGY §3.3).

## request_events (append-only)

| Field | Semantics | Written by |
|---|---|---|
| action | `REQUEST_CREATED`, `EDITED`, `SUBMITTED`, `RESUBMITTED`, `APPROVED`, `APPROVAL_FAILED_BUDGET`, `REJECTED`, `CHANGES_REQUESTED`, `CANCELLED` | system per action |
| actor_id / actor_role | Who acted (role at action time). Seed events have real seed users as actors; NULL is reserved for future system actions | system |
| from_status / to_status | Machine transition context (NULL on create) | system |
| step_level / step_sequence | Step context for approval-family actions | system |
| version_number | Business version the action referred to | system |
| comment | Decision comment when provided | system copies from request |
| x_request_id | Correlation id of the originating HTTP request (NFR-007); `seed` for seed events | `RequestIdFilter` → MDC → `AuditService` |
| occurred_at | UTC instant of the action | system |

No UPDATE/DELETE path exists (migration 005 revokes grants; trigger raises on violation).

## idempotency_keys

| Field | Semantics | Written by |
|---|---|---|
| idem_key | Client-generated `Idempotency-Key` header (README example: UUID) | client |
| endpoint | Scoped operation, `POST /requests` | system |
| payload_hash | SHA-256 of a canonical form of the request body (fixed field order, trimmed text, prices in cents) | `IdempotencyService` |
| response_status / response_body | First execution's response, replayed verbatim on retry. Reserved as a placeholder (`102`, `{}`) in the **same transaction** as the create — request row and key row commit atomically (A-32) | `IdempotencyService` (same transaction as the create) |
| expires_at | `created_at + 24 h`; expired records are ignored and lazily purged | system |
